# 山道猴王：操作同跑跑卡D車（北宜公路 WebGL 賽車）

純 WebGL2 手寫（沒有使用 three.js 或任何 3D 函式庫）的台灣山路駕駛遊戲。
賽道是以真實地理資料重建的 **台9線 北宜公路**，車輛是 **Honda Civic 六代（K8）四門 1.6 自排**。

## 怎麼玩

直接用 Chrome 或 Edge 開啟 `index.html` 即可（不需要架伺服器）。

選車畫面會隨目前的賽道切換背景：「彎道衝刺」是山路急彎、「熱浪夏威夷」是夕陽海岸競速插畫。背景使用 `images/backgrounds/` 的兩張 WebP（合計約 563 KiB），按需載入、快取並淡入切換；其他賽道使用原本的暗色背景。圖片只用於選單，進入比賽便隱藏。透明車庫畫布保留 3D 車輛旋轉、換車和車色操作，桌面、手機與直接開啟本機 HTML 皆可使用。內建 image_gen 的原始圖片與完整提示詞保存在 `assets/menu-backgrounds/`，上架包只包含 WebP。

選車背景單獨套用亮度 68%、飽和度 48%、對比 90%，壓低路牌與夕陽的視覺重量，讓車輛與性能燈條成為焦點；車身、介面及比賽場景不受這層濾鏡影響。

車庫以置中的 3D 車輛與車名為主體，右側顯示四項六格性能評級，下方可直接點選六款車與十四種塗裝；選中的車色有名稱與勾選標記。車輛閒置時會慢慢水平旋轉，拖曳可調整視角，並可按「重設視角」回到預設角度。手機直向版提供可左右滑動的塗裝列；地圖、設定視窗的關閉與確認按鈕保持可見。新版視覺樣式集中在 `css/garage.css`。

| 按鍵 | 功能 |
|---|---|
| ↑ | 前進 |
| ↓ | 煞車 / 倒車 |
| ← | 左轉 |
| → | 右轉 |
| CTRL | 氮氣加速 |
| SHIFT | 甩尾 |

自排變速箱由電腦自動處理（D/R 自動切換、1～4 檔自動換檔），不需要排檔。

### 起跑：倒數 3、2、1 與彈射起步

個人計時賽和多人房都一樣：載入完成後車子鎖在起跑格，畫面倒數 **3、2、1、START** 才放行。**START 那一刻就開始計時**，算到通過終點線（2026-11-25 起；之前是過起點線才開始算，所以起步的快慢現在也算在成績裡）。

**彈射起步**（同跑跑卡丁車的起步加速）：「1」數完、START 出現的那一瞬間按下 ↑，起跑時車尾會短噴火衝出去。

- 判定的是「按下去的那一下」，要落在 START 前 0.25 秒到後 0.15 秒之間。
- 「1」剛出現就按算按太早，這一次起步就沒有彈射（所以連打沒用）；從頭按著不放也沒有；太晚才按就是一般起步。
- 效果是 1.8 秒的噴射，不消耗氮氣瓶。喜美 K8 在彎道衝刺起點實測：起跑 1 秒後時速約 43 km/h（一般起步 18 km/h）、2 秒後約 76 km/h（一般 36 km/h），5 秒後領先約 36 公尺。

## 個人計時賽、多人房間、紀錄與積分

車庫右下角有兩種玩法，**成績共用同一份紀錄**：

- **個人計時賽**：自己跑。跑完依成績給分、更新賽道紀錄。
- **多人連線**（最多 4 人）：
  - 「多人連線」→ 左邊是**房間列表**（房名、房主、賽道、人數、碰撞開關），按「加入」進房；右邊**開新房間**，可以輸入房名、選賽道 / 方向 / 天氣、**開啟或關閉玩家碰撞**。
  - 進房後右側是房間面板（左邊照常換車、換色）。其他人按「準備」，房主按「開始比賽」；房主可隨時改「房間設定」或把人請出去，房主離開時由最早進房的人接手。
  - 全員載入完成後 **3、2、1、START** 同步起跑（一樣可以彈射起步），四台車並排在起跑線前。比賽中左側顯示即時名次，其他玩家頭上有名牌；多人比賽不能暫停，Esc 是「離開房間」。
  - 第一個人抵達終點後，其他人還有一段時間（冠軍時間的一半，30 秒～3 分鐘）可以跑完，逾時算未完賽。結算後按「回到房間」可以再開一場。
  - 碰撞開啟：玩家的車會互相擋住、卡位；關閉：互相穿透，各跑各的。多人比賽一律封路（沒有車流）。
- **賽道紀錄**：每條賽道 × 每個方向各有一份**前 15 名**（每位玩家只留最佳一筆；2026-11-25 由 5 名放寬），熱浪夏威夷也在內（單向，只有個人計時賽，不能開多人房）。車庫的地圖卡片上方會顯示目前所選地圖的**紀錄保持人與時間**，按一下看前 15 名；結算畫面列前 5 名，自己排在 6～15 名時另外補一列。
- **看重播**：**彎道衝刺（雙向）與熱浪夏威夷**的前 15 名，名次右邊有 ▶，按下去就能看那位玩家那一趟怎麼跑（畫面上只有他的車）。可以暫停（空白鍵）、倒退 / 快轉 5 秒（← →）、拖時間軸、0.5× / 1× / 2×、換視角（C，多一個路邊的「轉播鏡頭」），Esc 或「返回紀錄」回到紀錄視窗，車庫的車款與設定會還原。
  - 不是錄影：跑的時候每秒記 5 次車子沿道路的位置、橫向位置、車頭角度與離地高度（加上煞車、氮氣，以及 HUD 的氮氣瓶數與集氣條），壓縮後每分鐘約 0.6～0.9 KB，播放時再用遊戲引擎即時畫出來（`js/game/replay.js`）。物理跟著每台電腦的幀率走，所以不能只記按鍵再重算。
  - 平台給全部玩家共用的資料只有 64 KB（紀錄、房間列表也在裡面），所以只有這兩條短賽道有重播。紀錄掉出前 15 名、或自己跑出更好的成績蓋掉舊紀錄，舊的重播就刪掉；萬一空間還是不夠，從名次最後面的重播開始刪（紀錄本身不受影響）。
  - 加這個功能之前跑的紀錄沒有重播，要重跑一次進榜才會有 ▶。
  - 車子照那一趟的改裝畫（輪圈、彩繪、車高…，見「改裝工廠」）；挑戰的幽靈車也是。
- **挑戰（幽靈車）**：▶ 旁邊的「挑戰」= 用自己的車、車色、天氣跑那條賽道，那筆紀錄變成**半透明的幽靈車**一起跑（沒有影子、不碰撞，起跑時和自己的車疊在一起會淡一點）。成績照常送出、計分、列入紀錄。
  - 上方顯示挑戰的是誰、紀錄時間，以及即時的「領先 / 落後幾秒」（自己現在的位置，幽靈車是幾秒前 / 後跑到的）；幽靈車頭上有名牌；結算畫面多一列勝負。
  - 「再跑一次」繼續挑戰，回到車庫就結束。幽靈車的時間跟著自己的碼錶（兩邊都從 START 起算），資料就是重播（`js/game/replay.js` 的 `Ghost`）；半透明的畫法在 `js/render/renderer.js` 最後一個階段（先寫深度、再用固定透明度疊顏色）。
- **計時規則改了就重新計**：`server/functions.js` 的 `REC_V`（目前 2 = START 就開始計時）。版本不同的賽道前 15 名、重播、個人最佳一律當作沒有，改版上線後第一個開遊戲的人讀紀錄 (`profile`) 時就真的從共用資料刪掉（各玩家自己的舊個人最佳在他下次開遊戲時刪），**累計積分與完賽次數保留**；舊版遊戲送來的成績伺服器不收（請玩家重新整理）。玩家端送成績時帶的 `rv`（`js/ui/online.js`）和本機最佳的 `_r2`（`js/main.js` `_bestKey`）要一起改。
- **積分**：每跑完一趟就給分，一直累加，並同步到平台排行榜（右上角獎盃）。

  `積分 = 賽道公里數 × 100 × (平均時速 ÷ 80，限 0.3～2.2) × (1 + 加成)`

  | 加成 | |
  |---|---|
  | 零碰撞 | +15% |
  | 每碰撞一次 | −3%（最多 −30%） |
  | 多人第 1 / 2 / 3 名 | +30% / +15% / +5% |
  | 刷新個人最佳 | +10% |
  | 進入賽道前 5 名 / 成為紀錄保持人 | +20% / +50% |

直接開 `index.html`（沒有平台）時是**單機模式**：同一套計分規則在瀏覽器裡執行，紀錄只存在這台電腦，沒有多人連線。

## 上架到金碟遊樂場（GoldSaucer）

```
python tools/pack_goldsaucer.py      # → dist/shandao-monkey-king.zip（同時檢查平台的各項限制）
```

到平台的「上傳遊戲」選這個 zip 即可。包裡的重點：

| 檔案 | 用途 |
|---|---|
| `goldsaucer.json` | 入口、封面、房間腳本、伺服器函式、橫向 16:9 |
| `cover.jpg` | 封面（1280×800） |
| `server/functions.js` | 伺服器函式：算分、累計積分、賽道前 15 名、重播（只留前 15 名的）、房間登記簿（房名等，房間列表用） |
| `js/game/replay.js` | 重播：錄製、壓縮格式、播放（車身姿態 / 輪子 / 胎痕從軌跡推回來）、播放控制列 |
| `server/room.js` | 多人房間腳本：準備 / 開始、同步倒數、轉送車輛位置、名次與結算 |
| `js/net/platform.js` | 平台 SDK 串接（沒有 SDK 時退回單機模式） |
| `js/net/multiplayer.js` | 連線、狀態同步（每秒 12 次＋延遲補償）、其他玩家的車、碰撞 |
| `js/ui/online.js`、`css/online.css` | 房間列表 / 開房 / 房間面板 / 名次 / 結算 / 排行榜介面 |
| `js/game/start.js` | 起跑倒數 3、2、1、START 與彈射起步的判定（個人計時賽與多人房共用） |
| `js/world/drift_track.js`、`js/world/drift_theme.js` | 熱浪夏威夷：路形與路上設施、夏威夷夕陽海灘的場景 |
| `vendor/three/` | three.js r160（只用來解析車流的 glTF 模型；隨包附帶，不連外部 CDN） |

登入平台的玩家才有紀錄、積分與多人連線（平台規定）；訪客可以試玩個人計時賽。
完賽時間與碰撞次數由玩家端回報，伺服器只做合理性檢查（平均時速不可能超過約 300 km/h 等）。

### 在自己電腦上測試多人

```
node tools/dev_platform.js           # 不需要安裝任何套件
```

它會模擬平台（SDK、伺服器函式、房間腳本、排行榜），並印出網址。開兩個以上的分頁，網址的 `?user=` 不同就是不同玩家；
`?guest=1` 是訪客。`--latency 120` 可以模擬網路延遲，`--root <資料夾>` 可以改成測試解壓後的上傳包。

**上架前請用 `/play?user=…` 再測一輪**：它把遊戲包在和平台一樣的沙箱 iframe 裡。平台的沙箱不能送出表單（`<form>` 的 submit 事件不會觸發，按鈕要直接處理 click）、不能開新視窗或導走頁面，而且是「不透明來源」（`localStorage` 由平台的相容層提供）。直接開 `/` 沒有這些限制，問題會測不出來。

## 背景音樂

車庫右上角有一條精簡播放器：上一首、循環捲動的歌名、下一首。上下首依曲庫順序循環切換並播放，與設定裡的曲目選擇同步；連續點擊會依序跳曲。只有滑鼠移到歌名上才暫停跑馬燈，移到或聚焦上下首按鈕時繼續捲動；減少動態效果時顯示靜態歌名。手機直向時播放器移到頂部按鈕下方。

主選單「背景音樂」可選：關、Midnight Run · Evan Vale、Chasing Neon · Lila Cross、三點的風 · 林予川、隨機輪播（再按一次切下一首）。歌名與歌手為自訂虛構顯示名稱；播放器、設定與換曲提示統一顯示「歌名 · 歌手」。
選擇與音樂音量會記在瀏覽器裡。音檔放在 `audio/bgm1~3.mp3`，曲名清單在 `js/game/music.js` 的 `TRACKS`，要加歌就在這裡加一行。

## 賽道（真實資料；彎道衝刺段為遊戲重新設計）

- 道路中心線：OpenStreetMap（經 OSRM 路線規劃，全程確認在台9線上），新店北宜路一段 → 小格頭 → 坪林 → 石牌縣界 → 九彎十八拐 → 頭城，共 58.3 km。
- 地形高程：AWS Terrain Tiles（SRTM），25 m 網格，範圍涵蓋雪山山脈北段、蘭陽平原與龜山島。
- 路面高程由 DEM 平滑後取得（海拔 12～558 m，最大坡度 9.5%），九彎十八拐髮夾彎半徑約 10 m。
- 台9線里程依新北市交通局資料校正（坪林 38K、縣界 56K+661）。
- 區間測速：坪林區 33.3K～37.2K，限速 40。
- 路寬：雙向四車道（每車道 3.6 m，中間雙黃線、同向白虛線）+ 路肩，半寬 8.4 m（真實北宜約 4 m 的兩倍，方便駕駛與甩尾）；九彎十八拐髮夾彎內側會依轉彎半徑自動收窄。
- 封路模式：主選單「車流」選「🚧 封路模式」，路上不會有其他車。

可選路段：**彎道衝刺**（預設）、九彎十八拐（石牌→頭城）、坪林→頭城、新店→坪林、全程，雙向皆可。

彎道衝刺是台9線 30.6K～32.7K（北宜路六段→七段，石碇／坪林區界一帶）共 2.08 km，原本是全線彎道最密集的區段。**這一段的路形已為遊戲性重新設計**（其餘路段仍為真實路形）：原始資料有 22 個大小相近的彎、彎間直線只有 4～78 m，跑起來一直在轉、集到的氮氣沒地方用；改為 13 個有特色的彎 + 15～140 m 的直線：

起跑直線 → ①高速右掃彎 → ②大左 U（最長的甩尾集氣彎）→ ③～⑥連續 S（左右連飄）→ ⑦髮夾 → 山頂直線 → ⑧假動作接⑨髮夾 → 緩彎 + 直線 → ⑩⑪左右連彎 → ⑫ → 長直線 → ⑬ → 終點直線

- 每個彎都是「緩和曲線 + 圓弧 + 緩和曲線」，曲率漸增，入彎不突兀；髮夾半徑 25 m、掃彎 40～57 m。
- 以最佳化求解直線長度與彎的角度/半徑：兩端與原路的位置、方向完全接合，總長不變（下游里程、區間測速、其他路段都不受影響），平均偏離原路約 15 m；路面高程依新位置的地形調整，坡度上限 10%。
- 分段計時點：「大U彎」「雙髮夾彎」。起終點都在直線上，雙向起跑都順。
- 設計參數在 `js/world/road.js` 的 `EDITS`；把 `TRACK_EDIT` 改成 `false` 即還原真實路形。

以遊戲車輛物理 + 自動駕駛（急彎甩尾、直線用氮氣）實測，與原路形相比：往宜蘭 1 分 22 秒（原 1 分 25 秒）、往台北 1 分 26 秒（原 1 分 30 秒）；平均每次甩尾 2.5～2.7 秒（原 1.8 秒），一趟可集到並用掉 3～4 瓶氮氣（原 0～1 瓶，集滿也沒地方用）。以上是加入起步輔助與各車性能調校之前、以喜美 K8 量得的數據；調校後同樣的跑法，K8 每趟約再快 1～2 秒。

### 熱浪夏威夷（虛構賽道，單向下坡 3.36 km）

不在台9線上的自創賽道，個人計時、乾地封路。成績和其他賽道一樣送到平台（賽道前 15 名、積分，賽道代碼 `drift`、單向），分段時間只存在本機；不能開多人房。路形若再改到長度或難度不同，`server/functions.js` 的 `drift` 要改成新的賽道代碼，讓線上紀錄重新開始。整條路由 `js/world/drift_track.js` 的「直線 / 彎 / 複合彎」清單與坡度表產生，地面跟著道路自動堆出來。參考彎道衝刺的做法重新設計過：前半段彎更緊、彎與彎之間更短，高速路段更多，高低起伏更大，還有一處要飛過去的斷崖。

起跑直線俯衝 → 高速 S 彎 → 谷底回頭彎（R27）→ 上坡左彎，坡頂直接切進**盤旋匝道**（一圈，半徑 60 → 40 m 越轉越緊）→ 複合匝道爬上山脊 → **長陡坡**（坡度 16.5%，助跑 250 m）→ **斷崖飛越**（缺口 40 m，要時速 180 以上）→ 落地後 V 形谷底接陡上坡（緩衝 420 m）→ 谷底大彎（R105）→ 城鎮連續彎（R48～50 × 3，彎裡陡、彎間平，一層一層往下）→ 跳坡 → 三個駝峰高速彎 → 終點

- 起伏：全程下降約 194 m、其中幾段上坡共爬升約 42 m（改版前幾乎是一路緩下坡，爬升不到 5 m）；坡度 +11% ～ -18%。
- 車速：喜美 K8 自動駕駛一圈約 1 分 55 秒～2 分，時速 100 以上的時間約 52 秒（改版前 24 秒），長陡坡用氮氣極速約 225 km/h（改版前 195）。
- 難度：前半段髮夾半徑 27～30 m（改版前 33～37 m）、技術路段路寬收窄到半寬 8.8 m，開得太兇會擦牆（改版前怎麼開都不會撞）。飛越之後的彎則刻意放大，因為進彎前車速很高。
- 分段計時點：「環匝出口」「斷崖落地」「谷底直角彎」。路線每改一次，舊紀錄就不沿用（`recordVersion`）。

**斷崖飛越**：長陡坡上的高架橋斷了 40 m，**起跳時速要 180 以上才飛得過**（六台車實測的門檻都在 174～183 之間）。坡頂到斷口有 250 m 助跑：不用氮氣時喜美 K8 只到 151、AE86 161、GR86 174、911 178、R34 179，都差一點，只有 R35（209）不用氮氣也過得去，所以要把氮氣留到長陡坡用（K8 用兩瓶約 209、R35 約 250）。飛過去滯空約 0.7～1 秒，落在對岸橋頭後 0～30 m；不夠快會從對岸橋面下方掉進溪谷，然後從對岸的落地區重新出發（車速歸零）。

**落地之後**：落地區 50 m 後由下坡轉成 11% 的陡上坡，放開油門車速就會自己掉（K8 落地 210，不踩煞車滑到谷底彎剩約 174），上坡煞車也比較短、比較穩；一般反應（落地後 1 秒才踩煞車）要把車速降到進彎的 120 km/h 需要 180～260 m，緩衝有 420 m。谷底彎是半徑固定的 R105 大彎。

**飛越路段的穩定輔助**（只在長陡坡到谷底彎前這一段，其他路段與北宜完全不受影響）：
- 空中：方向盤自動回正，行進方向慢慢帶回順著道路，車頭對準行進方向。起跳前就算點過方向鍵，落地也是直的，不會像被甩尾一樣打轉。
- 地面：時速 130 以上方向鍵的舵角漸漸收小（180 以上約 3°），車頭跟著行進方向走；高速時用鍵盤修正方向、落地後重踩煞車都不會把車甩出去。

調整用的參數：
- 斷崖：`drift_track.js` 的 `cliff`（位置、缺口長度、落差、起跳與落地坡度）。門檻車速用落差 `drop` 調：對岸每低 0.1 m，門檻約降 2.5 km/h（6.35 m = 180）。
- 落地後的緩衝長度是 `runout`，谷底彎與城鎮彎的半徑是 `valley`、`hairpins`。
- 道路本身支援缺口：道路資料加上 `gaps: [[起點, 終點, 深度, 前, 後]]`（公尺），`js/world/road.js` 就不鋪那一段路面、物理地面改在下方，並把缺口「前」到「後」標成飛越路段（四輪離地時不額外加重力，其他地方仍照舊把車拉回地面）；穩定輔助在 `js/car/vehicle.js`，掉落後的重生在 `js/main.js`。

**場景：夏威夷夕陽海灘**（`js/world/drift_theme.js`，只管外觀，路形與物理完全不受影響）
- 天空：固定用 `renderer.js` 的 `ENV.miami`。太陽壓在東南方 7° 的海平線上，天頂深紫、地平線粉橘；長陡坡、斷崖、終點直線都正對著夕陽。天空的兩個可選參數 `skyCurve`（地平線色帶的寬窄）、`disk`（太陽圓盤亮度）其他天氣沒有設，維持原樣。
- 地形：整張圖是一座島。終點直線的左手邊是一長條沙灘與大海（海平面在終點直線下方約 6 m），地圖外緣都沉進海裡；內陸平地是跟海岸平行的棋盤街區（地面顏色畫出街道與鋪面）。
- 海：岸邊碧綠色的淺灘與浪花（水的著色器多一個「淺水程度」頂點屬性，北宜的海沒有這個屬性，畫法不變）。
- 景物：約 700 棵棕櫚樹、粉彩色的裝飾藝術旅館（遮陽簷、圓角塔、霓虹燈條）、沿海一整排海景公寓、約 800 棟內陸低樓層、救生員小屋、陽傘、路燈、帆船，海的對岸還有一排天際線。
- 材質：路牌的反光漆面、金屬框與螺栓；護欄的混凝土毛孔、每 6 m 接縫、底部污痕、倒角與反光片；草地、沙紋、岩層、棕櫚樹幹與葉脈、建築粉刷牆、木板、鍍鋅金屬及布料皆有獨立紋理。柏油凹凸直接沿用既有貼圖取樣。
- 效能：保留 256 m 分塊與視野／陰影剔除。新增材質共用一張 12 層、每層 256² 的線性紋理陣列，RGBA 分別儲存明暗、雙軸凹凸與粗糙度，含 mipmap 約 4 MiB；只在載入時產生。近景通常一次取樣，高畫質細節在 70～180 m 淡出（低／中／極高畫質的最遠距離為 75／120／220 m），遠景跳過細節取樣，地面保留低頻明暗；獨立 mipmap 避免材質串色。路牌固定件與護欄倒角合入原網格，整島三角形約增加 6.4%，五個測試路段的繪製呼叫數均與修改前相同。實際幀率仍取決於裝置與畫質。
- 材質參數：`textures.js` 的 `T.surfaces()` 產生 12 種材質；`shaders.js` 的物件材質模式 20～31 對應各層，32 使用地面 UV 中的沙灘／岩坡／鋪面權重。一般物件的貼圖以世界公尺投影，葉片沿自身 UV；路形、碰撞邊界、斷崖缺口與紀錄版本皆不變。
- 要改氣氛：天空顏色在 `ENV.miami`；海平面、海岸線位置、地面顏色、各種景物的數量與樣式都在 `drift_theme.js`。

## 改裝工廠

車庫選車面板最下方的「改裝工廠」。點零件會先**試裝**在展示車上（還沒買也看得到外觀與性能變化），滿意再買。車庫的性能欄滿分 10（原廠分數不變），改裝加成用亮藍色格子與小數 (+1.5 之類) 顯示，代價（扣分）用紅色格子與 −0.3 之類顯示。

**零件是複合式的，不是越貴越強**（2026-11-25 重新設計）：同一個部位的零件各有個性，一個零件會同時動到好幾項性能，有些還有代價；特定零件裝在一起還有**搭配加成**。實測「每個部位都買最貴的」反而比針對性的組合慢（彎道衝刺單圈 −2.3～−3.3 秒 vs 極速調校 + 直通排氣 + 甩尾零件 −4～−6 秒）。

- **錢**：籌碼。在平台上用紅鑽兌換，**1 紅鑽 = 100 籌碼**（`goldsaucer.json` 的 `currency`，平台會跳出確認；沒花完的籌碼離開遊戲時平台自動換回紅鑽）。直接開 index.html 的本機模式按「兌換」會直接加籌碼（測試用，不用紅鑽）。

| 雨戰 | 雨胎 + 六活塞 (打孔碟) | 雨天抓地、煞車再提升 |

性能評級的權重 (`ratingOf`) 是用 Node 直接跑車輛物理量出來的（彎道衝刺自動駕駛單圈 + 平地加速 / 極速 / 煞車），例如動力 +10% 單圈快約 0.7 秒、氮氣 +10% 快約 0.7 秒、甩尾掉速 −10% 快約 0.7 秒、集氣 +10% 只快約 0.1 秒（氮氣本來就常滿瓶）。量測時發現的幾件事也改進了：
- 輪圈轉動慣量對加速幾乎沒影響，輕量輪圈改成以起步、車重表現。
- 煞車力加大：原廠煞車就夠力的車 (GR86、R35 …) 煞車距離不會變短，只有煞車偏弱的車 (K8) 有感，所以卡鉗的個性靠其他效果。
- 後輪抓地調低只會更不穩、更常撞牆，不會更好甩，甩尾胎的代價改成整體抓地略低 + 起步軟。
- 紅線提高原本會讓自排拖到扭力掉下去才換檔 (反而變慢)，現在扭力曲線會跟著往高轉拉長。
- 甩尾噴射 (`boost`) 疊加上限 +20%、甩尾掉速 (`dDrag`) 最多 −20%，疊太多會常擦到彎道內側的牆。
- K8 的規格以前直接回傳共用的 `RM.CIVIC_SPEC`，改裝套用時會改到它 (每開一場就再疊一次加成)，現在每次給一份新的。

十套彩繪涵蓋競技雙線、紅黑圖騰、格旗流線、美式手工拉線、廠隊車號、墨色山嶺、復古圓牌、海岸曲線、MK 車隊與夜櫻。簡潔識別與全車主題並存，較大圖案用曲線、尖端、山勢及花枝延伸到引擎蓋與車頂。深色車漆會將可變主識別改為淺灰，固定配色與號碼牌維持原本對比。左右側文字分別排版，貼圖分區有裁切，避免圖案溢入另一側。改裝工廠提供樣式縮圖、配色與立體／左右側／俯視切換；既有彩繪 ID、等級及價格沿用。

設計比例參考：[Porsche Carrera T 的低位側裙識別](https://newsroom.porsche.com/en_AU/2022/products/porsche-new-911-carrera-t-touring-world-premiere-30097.html)、[911 S/T Heritage 的獨立號碼圓牌](https://newsroom.porsche.com/en/press-kits/911-s-t/Heritage-Design-Package.html)、[NISMO Z-tune 的整車配置](https://www.nismo.co.jp/nismo_history/complete_car/vol_03/)。遊戲內圖形與字標為原創，參考圖片未加入遊戲資源。

- **鋁圈 / 輪胎 / 煞車的產生器**是 `js/car/wheel_builder.js`（`proc_car.js buildWheel` 交給它，原廠輪圈也用同一套）：
  - 輪胎：真實斷面、胎肩橫向溝、胎壁的真文字（白字或原廠深灰模壓字）。
  - 輪緣：J 型捲邊、階梯外唇、內側中央凹槽。
  - 輻條：沿半徑的寬度曲線（兩端圓角過渡）、凹度曲線、厚度漸變；斷面分圓潤／中等／銳利倒角三種，可加中央切削溝與肋貼紙。
  - 輪轂：凹陷的螺帽座與六角螺帽、中心蓋徽章、氣嘴。
  - 煞車：通風碟的風道與導流片、打孔／劃線／浮動碟；卡鉗圓角鉗體、活塞座、字樣、放氣螺絲。
  - 材質是 `shaders.js` 一般物件著色器的鋁圈模式：40 車削（圓周車削紋 + 放射狀異向反光）、41 烤漆（透明漆 + 金屬亮片）、42 陽極霧面、43 橡膠、44 拉絲。字樣與徽章共用一張 1024² 貼圖（`WheelBuilder.texture()`）。
- 程式：零件目錄與性能 `js/game/tuning.js`、外觀 `js/car/tuning_vis.js`（各款輪圈的造型參數與材質在 `wheelOpts`；彩繪是一張 2048×1024 貼圖由車殼著色器疊在烤漆上）、貼紙與彩繪組合 `js/car/livery_data.js`、介面 `js/ui/tuning_ui.js`、伺服器 `server/functions.js` 的 `buyMod` / `fitMod`（價格以伺服器為準，用戶端和伺服器的 id／價格要一致）。
- **看重播、挑戰的幽靈車、多人連線裡別人的車都照那位玩家的改裝畫**（輪圈、卡鉗、排氣管、彩繪、車身降低與外傾；重播的引擎聲、換檔點也跟著他的規格）。靠的是一段「改裝代碼」（`tuning.js` 的 `code` / `fromCode`，例如 `w_deep.1/t_drift/s_street.2/b_6pot.3/e_ti/lv_flame/3.2` = 輪圈.顏色 / 輪胎 / 避震.顏色 / 卡鉗.顏色 / 排氣管 / 彩繪 / 寫電腦階數.調校方向，全原廠是空字串）：
  - 重播：送成績時伺服器用**自己存的改裝資料**算出代碼（`functions.js` 的 `fitCode`，不收玩家端送的），存在重播的 `m`；最長約 60 字元，前 15 名 × 3 榜全部帶滿也只多約 3 KB。沒有 `m` 的舊重播照原廠畫。
  - 多人：進房的 `hello` 帶自己的代碼（車庫裡換零件會重送），房間腳本 `server/room.js` 放進起跑名單 `grid` 轉給每個人。
  - 改裝過的車和原廠車在同一個賽道紀錄榜上。

車款外形與規格為依公開資料手工調出的近似值，非官方授權；車牌為虛構。

選車畫面顯示目前車款的「速度、加速度、飄移、操控性」，每項最多十格亮燈；換車時依左右方向快速滑動，新舊車過場同時進行（動畫各 220 毫秒，另加模型建立時間），性能燈格依序點亮。展示地面使用透明接地陰影、雙軌燈帶與角標，取代圓盤底座，並隨拖曳視角一起轉動。系統開啟減少動態效果時直接切換；縮放視窗或離開車庫會清除過場。

主畫面閒置時車輛會慢慢水平自轉（每分鐘一圈），保留目前的俯仰角。拖曳時立即停止，放開或用方向鍵調整後等待 1.2 秒，再平滑恢復自轉。換車過場、開啟對話框、隱藏分頁與比賽中不自轉；系統啟用減少動態效果時維持靜止，仍可手動拖曳。

六格是依遊戲內調校設定的相對評分（`js/ui/menu.js` 的 `PERFORMANCE`），不是原廠規格或即時測速，也不影響駕駛物理。速度與加速度參考目前動力表現；飄移綜合甩尾角、保速與集氣能力；操控性綜合轉向、抓地與上手難度。調整車輛物理時應一併檢視評分。

為縮短換車等待，車庫使用 2048 貼圖並快取最近三款預覽；進入比賽時釋放這些預覽，玩家比賽用車仍依原規則建立完整解析度貼圖（最高 4096）。

**車款平衡（2026-11-25）**：速度可以有快慢但不能差太多，每台車各有強項。原廠規格差距太大（K8 0–100 要 9.8 秒、極速 181；R35 3.8 秒、330），所以各車款規格多了 `power`（動力倍率，扭力表維持原廠數字，`makeSpec` 乘上去），再一起調起步輔助、風阻、甩尾 / 氮氣。使用者看過第一版後說極速差距 (221～299) 還是太大，再縮到 242～267 km/h（R35 仍最快）。車庫顯示的排氣量 / 馬力仍是原廠數字。

各車性能（Node 直接跑車輛物理：平地鍵盤油門；單圈是彎道衝刺自動駕駛甩尾跑法，雙向 × 三種開法平均）：

| 車輛 | 0–100 km/h | 極速 | 彎道衝刺單圈 | 強項 / 甩尾與氮氣的特色 |
|---|---|---|---|---|
| 喜美 K8 | 5.9 秒 | 250 km/h | 77.6 秒 | 好上手：起步輔助最大、抓地稍強、氮氣與出彎小噴射稍強（動力 ×1.6） |
| AE86 | 6.0 秒 | 242 km/h | **76.8 秒** | **甩尾最快**：甩尾角最大、甩尾中最不掉速、集氣最快；直線最弱（動力 ×1.18；原廠尾牙 4.3 在五檔紅線只有 224 km/h，改 3.8） |
| GR86 | 5.2 秒 | 254 km/h | 77.8 秒 | 均衡；甩尾角略小、弧線略大；氮氣強（動力 ×1.12） |
| 911 Carrera RS | **4.4 秒** | 255 km/h | 77.5 秒 | **起步 / 加速最快**：起步輔助最強、彈射起步最猛；甩尾中掉速稍多（動力 ×1.12） |
| Skyline GT-R R34 | 4.8 秒 | 261 km/h | 77.7 秒 | 加速與極速都第二快、四驅抓地；甩尾角小、集氣稍慢（動力 ×1.05） |
| GT-R R35 | 4.5 秒 | **267 km/h** | 77.7 秒 | **極速最高**、氮氣推力最大；甩尾最弱（原廠 570 PS 太強，動力 ×0.85、風阻加大到 0.49） |

- 調整時注意：甩尾中的減速（`drift.drag`）調低單圈快很多，但 GR86 這類車寬馬力大的車會常擦到彎道內側的牆，GR86 因此改加氮氣。

- 起步輔助：前進檔、沒在甩尾時，低速依油門多給一股推力，10 km/h 以下全力、65 km/h 歸零（規格的 `launch`）。上坡起步也不會拖。
- 彈射起步：`Vehicle.startBoost()`，1.8 秒、推力 = 氮氣推力 + `drift.start`（預設 8000 牛頓）；按鍵的判定範圍是 `js/game/start.js` 的 `WINDOW`。
- 甩尾與氮氣的車款差異在規格的 `drift`（甩尾角、轉彎速度、甩尾中的減速、集氣速度、出彎小加速與氮氣的推力）；沒列的項目沿用喜美 K8 的數值。
- 喜美 K8 的基礎數值在 `js/car/vehicle.js` 的 `SPEC`（也是其他車款沒列項目的預設值），平衡用的覆寫在 `js/car/civic_model.js` 的 `BAL`；其餘在各車款檔的 `SPEC_OVER`。
- 底盤配重（規格的 `plant`，全車款共用、依車重縮放）：讓車像底盤很重、重心很低一樣不容易翻、不容易飛。只在超出正常行駛範圍時介入，平常的加速、極速、過彎與甩尾不變。
  - 車身相對路面傾斜超過 7 度（`tilt`）才把車身壓回來（`roll` / `pitch` 力道、`damp` 阻尼）；正常過彎的側傾約 5 度以內。
  - 撞護欄 / 山壁的反作用力一律作用在重心高度，貼著牆甩尾不會被撬起來。
  - 離開柏油的輪子，懸吊力上限 1.5 倍車重（`fz`）：壓到水溝、路緣不會整台被彈起來。
  - 四輪全部離地時多加 1 倍重力（`air`），飛不高也飛不遠。
  - 想讓某台車更容易 / 更不容易翻，在該車款檔的 `SPEC_OVER` 加 `plant: { ... }` 覆寫；`roll`、`pitch` 設 0 即關閉壓回。

作法（共用工具在 `js/car/proc_car.js`，新增車款只要再寫一個車款檔並登錄）：

- 車殼：用數學函式描述車身曲面（下車身 + 座艙，各面以圓角相接），再取樣成平滑網格。
- 細節：尾燈、頭燈、鈑件縫、車窗、飾條畫成貼圖，以「環繞車身一圈」與「俯視」兩個投影貼到車殼上，含凹凸與材質。
- 零件：輪胎與鋁圈（深唇、立體輻條、螺帽、中心蓋）、通風碟盤與不隨輪子轉動的卡鉗、輪拱內襯、後照鏡、內裝、車牌與標誌貼片。

路上車流用 **three.js**（GLTFLoader，從 jsDelivr 載入）解析 Kenney Car Kit（CC0）的模型：轎車、休旅、計程車、廂型車、警車、小貨車、救護車、垃圾車、消防車，加上遊覽車與機車。需要網路連線載入 three.js，離線時車流改用簡易模型。被撞時：機車會被撞飛、汽車互相碰撞、大車（遊覽車、垃圾車、消防車）推不動。

重新打包車流模型：`python -I tools/build_car_assets.py`（輸出 `js/data/car_assets.js` 與 `assets/models/`）。

## 效能

瓶頸在顯示卡（CPU 端物理、車流、HUD 合計不到 1 ms），所以優化集中在「少畫、晚畫、畫便宜一點」：

- **地形 LOD**（`js/world/terrain.js`）：500 m 方塊、6.25 / 12.5 / 25 / 50 m 四級網格，外圍 2 km 遠景方塊（100 / 200 m）。高解析度網格只鋪在相機周圍，地形三角形由每幀 43～62 萬降到約 14 萬。
- **繪製順序**（`js/render/renderer.js`）：車 → 物件 → 道路 → 近景樹 → 地形 → 遠景樹。近的先寫入深度，鋪滿畫面的地形晚畫，被擋住的像素不必跑著色器；近景樹與地形方塊也都由近到遠排序。
- **陰影**：範圍中心往鏡頭前方偏移（背後看不到的地方不算），貼圖因此可以縮小而清晰度不變；只把落在陰影範圍內的樹送進陰影貼圖；取樣由 9 次減為 4 次（樹葉 1 次）。
- **玩家車**（`js/car/proc_car.js` 的 `shellExtras`）：車殼約 9 萬個三角形，原本每幀畫 4 次。陰影改用低模（約 5 千），車窗兩道只畫含玻璃的三角形（約 1.5～2 萬），輪子的陰影用圓柱代替。
- **樹葉光照**：只算漫射、環境光與車燈，不算高光與天空反射。
- 各畫質的陰影貼圖大小、地形細緻度、貼圖各向異性過濾都在 `js/main.js` 的 `QUALITY` 表。
